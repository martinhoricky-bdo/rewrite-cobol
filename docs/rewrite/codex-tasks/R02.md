Zásady:

- Názvy tabulek a sloupců = legacy názvy malými písmeny (`db_table`, `db_column`). Názvy polí modelů jsou stejné jako sloupce, **kromě cizích klíčů**: FK pole se jmenuje bez `id` (`dept`, `airplane`, `airportdep`, `client`, `flight`, `buy`, `emp`, `shift`, `crew`), sloupec zůstává legacy (`db_column="deptid"`). Django pak nabízí `flight.airplane` (objekt) i `flight.airplane_id` (hodnota).
- `DEFAULT_AUTO_FIELD` je `AutoField` (INT), nastaveno v R01.
- Žádné views, formuláře ani seed – jen modely, migrace, admin, sekvence, factories, testy.
- Nic mimo `app/` a `docs/rewrite/CHANGELOG.md`; žádné `.github/workflows/`.

## Rozsah – modely

Vytvoř aplikace `fleet`, `operations`, `sales` (přidej do `INSTALLED_APPS`) a rozšiř `accounts`.

### accounts

**`Department`** – `db_table = "dept"`

| Pole | Typ | Poznámka |
|---|---|---|
| `deptid` | `IntegerField(primary_key=True)` | ruční PK 1–9 |
| `name` | `CharField(max_length=20)` | |
| `manager` | `ForeignKey("Employee", null=True, blank=True, on_delete=PROTECT, db_column="manager", related_name="managed_departments")` | cyklus s `Employee.dept`; Django na PostgreSQL vytváří FK jako `DEFERRABLE INITIALLY DEFERRED`, nic dalšího není třeba |

**`Employee`** – `db_table = "emplo"`

| Pole | Typ |
|---|---|
| `empid` | `CharField(max_length=8, primary_key=True)` s validátorem `^\d{8}$` |
| `firstname`, `lastname` | `CharField(30)` |
| `addre` | `CharField(100)` |
| `city` | `CharField(50)` |
| `zipcode` | `CharField(15)` |
| `telephone` | `CharField(20)` |
| `email` | `EmailField(max_length=100)` |
| `admidate` | `DateField()` |
| `salary` | `DecimalField(max_digits=8, decimal_places=2)` |
| `dept` | `ForeignKey(Department, on_delete=PROTECT, db_column="deptid", related_name="employees")` |
| `user` | `OneToOneField(settings.AUTH_USER_MODEL, null=True, blank=True, on_delete=SET_NULL, db_column="user_id", related_name="employee")` |

Dále v `accounts/roles.py`: `class Role(models.TextChoices)`: `CEO="ceo"`, `CREW="crew"`, `HR="hr"`, `IT="it"`, `SALES="sales"`, `LEGAL="legal"`, `SCHEDULE="schedule"`; `ROLE_BY_DEPT = {1: CEO, 2: CREW, 3: CREW, 4: CREW, 5: HR, 6: IT, 7: SALES, 8: LEGAL, 9: SCHEDULE}`. `Employee.role` (property) vrací `ROLE_BY_DEPT[self.dept_id]`; `Employee.full_name` vrací `"{firstname} {lastname}"`. `Meta.ordering = ["empid"]`.

### fleet

**`Airport`** – `db_table = "airport"`: `airportid CharField(4, primary_key=True)`, `name CharField(100)`, `address CharField(250)`, `city CharField(30)`, `country CharField(30)`, `zipcode CharField(15)`. `ordering = ["airportid"]`.

**`Airplane`** – `db_table = "airplane"`: `airplaneid CharField(8, primary_key=True)`, `type CharField(8)`, `numseats PositiveIntegerField()`, `totalfuel PositiveIntegerField()`. `CheckConstraint(numseats__gt=0, name="airplane_numseats_positive")`.

### operations

**`Crew`** – `db_table = "crew"`: `crewid AutoField(primary_key=True)`; `commander`, `copilote`, `fachief`, `fliattendant1`, `fliattendant2`, `fliattendant3` – každé `ForeignKey(Employee, on_delete=PROTECT, db_column=<stejný název>, related_name="crews_as_<název>")`. Metoda `members()` vrací seznam šesti zaměstnanců; `clean()` vyhodí `ValidationError`, pokud nejsou všichni různí.

**`Shift`** – `db_table = "shift"`: `shiftid AutoField`, `shiftdate DateField`, `begintime TimeField`, `endtime TimeField`, `crew ForeignKey(Crew, PROTECT, db_column="crewid", related_name="shifts")`. `CheckConstraint(begintime__lt=F("endtime"), name="shift_begin_before_end")`. Index `(shiftdate)`.

**`Flight`** – `db_table = "flight"`

| Pole | Typ |
|---|---|
| `flightid` | `AutoField(primary_key=True)` |
| `flightdate` | `DateField()` |
| `deptime`, `arrtime` | `TimeField()` |
| `totpass` | `IntegerField()` |
| `totbagga` | `IntegerField(default=0)` |
| `flightnum` | `CharField(6)` s validátorem `^CB\d{4}$` |
| `shift` | `ForeignKey(Shift, PROTECT, db_column="shiftid", related_name="flights")` |
| `airplane` | `ForeignKey(Airplane, PROTECT, db_column="airplaneid", related_name="flights")` |
| `airportdep` | `ForeignKey(Airport, PROTECT, db_column="airportdep", related_name="departures")` |
| `airportarr` | `ForeignKey(Airport, PROTECT, db_column="airportarr", related_name="arrivals")` |
| `price` | `DecimalField(max_digits=7, decimal_places=2, default=Decimal("120.99"))` |

Constraints a indexy: `UniqueConstraint(fields=["flightnum", "flightdate"], name="flight_flightnum_flightdate_uniq")`, `CheckConstraint(~Q(airportdep=F("airportarr")), name="flight_airports_differ")`, `Index(fields=["flightdate", "deptime"], name="flight_date_deptime_idx")`, `Index(fields=["flightnum"], name="flight_flightnum_idx")`. `ordering = ["flightdate", "deptime", "flightnum"]`. `__str__` → `"CB1104 2022-09-01"`.

### sales

**`Passenger`** – `db_table = "passengers"`: `clientid AutoField`, `firstname CharField(30)`, `lastname CharField(30)`, `address CharField(250)`, `city CharField(50)`, `country CharField(30)`, `zipcode CharField(15)`, `telephone CharField(18)`, `email EmailField(100)`. Index `models.Index(Upper("lastname"), Upper("firstname"), name="passengers_name_upper_idx")` (funkcionální index, `django.db.models.functions.Upper`). `full_name` property. `ordering = ["lastname", "firstname", "clientid"]`.

**`Buy`** – `db_table = "buy"`: `buyid AutoField`, `buydate DateField`, `buytime TimeField`, `price DecimalField(7, 2)`, `emp ForeignKey(Employee, PROTECT, db_column="empid", related_name="sales")`, `client ForeignKey(Passenger, PROTECT, db_column="clientid", related_name="buys")`. Index `(buydate)`.

**`Ticket`** – `db_table = "ticket"`: `ticketid CharField(10, primary_key=True)` s validátorem `^CB\d{8}$`, `buy ForeignKey(Buy, PROTECT, db_column="buyid", related_name="tickets")`, `client ForeignKey(Passenger, PROTECT, db_column="clientid", related_name="tickets")`, `flight ForeignKey(Flight, PROTECT, db_column="flightid", related_name="tickets")`, `seat CharField(3)` s validátorem `^[A-F]\d{2}$`. `UniqueConstraint(["flight", "seat"], name="ticket_flight_seat_uniq")`, `UniqueConstraint(["flight", "client"], name="ticket_flight_client_uniq")`. (Indexy nad FK Django vytváří automaticky.)

**Sekvence letenek:** migrace v `sales` s `migrations.RunSQL("CREATE SEQUENCE ticket_ticketid_seq START WITH 1", "DROP SEQUENCE ticket_ticketid_seq")`. Do `sales/services.py` funkce `next_ticket_id() -> str`: `SELECT nextval('ticket_ticketid_seq')` → `f"CB{n:08d}"`. Funkce `reset_ticket_sequence()` nastaví sekvenci na `max(číslo z existujících ticketid) + 1` (použije ji seed/import).

### Admin, factories

- Registruj všechny modely v Django adminu (`list_display` s hlavními poli, `search_fields` pro ID a jména).
- `tests/factories.py` (`factory_boy`, `DjangoModelFactory`) pro všechny modely: `DepartmentFactory` (deptid sekvence od 1, name), `EmployeeFactory` (empid `1000{n:04d}` od `10000001`, dept), `AirportFactory` (3písmenné kódy ze sekvence), `AirplaneFactory` (numseats 150), `CrewFactory` (6 různých zaměstnanců), `ShiftFactory`, `FlightFactory` (flightnum `CB{n:04d}`, různá letiště, price 120.99, totpass = airplane.numseats), `PassengerFactory`, `BuyFactory`, `TicketFactory` (ticketid přes `next_ticket_id()`, seat `A01` s sekvencí).

## Testy (`tests/unit/`)

1. `test_schema.py`: po migraci existují tabulky `airport, airplane, dept, emplo, crew, shift, flight, passengers, buy, ticket` (dotaz do `information_schema.tables`); ve `flight` existuje sloupec `price`, v `ticket` sloupec `seat`, v `emplo` sloupec `deptid`.
2. `test_constraints.py`: `IntegrityError` při druhém letu se stejným `flightnum` + `flightdate`; při stejném `seat` na stejném letu; při stejném `client` na stejném letu; při letu s `airportdep == airportarr`; při směně s `begintime >= endtime`; při letadle s `numseats = 0`.
3. `test_ticket_sequence.py`: `next_ticket_id()` vrací `CB00000001`, pak `CB00000002`; `reset_ticket_sequence()` po ručním vložení `CB00000010` způsobí další `CB00000011`.
4. `test_roles.py`: `Employee.role` pro dept 1–9 dle `ROLE_BY_DEPT`; `full_name`.
5. `test_crew.py`: `Crew.clean()` vyhodí `ValidationError` při duplicitním členovi.
6. `test_factories.py`: každá factory vytvoří platný objekt (`full_clean()` projde).

## Akceptační kritéria

1. `make migrate` z čistého stavu projde; `make check` zelený; `makemigrations --check --dry-run` bez změn.
2. Názvy tabulek a sloupců odpovídají tabulce výše (ověřeno testem 1).
3. Všechny constraints, indexy a sekvence z tohoto zadání existují (testy 2–3).
4. Admin zobrazí všechny modely (view test `GET /admin/` jako superuser → 200 a seznam obsahuje názvy modelů).
5. `docs/rewrite/CHANGELOG.md` má záznam R02. Změny jen v `app/` a CHANGELOG.
