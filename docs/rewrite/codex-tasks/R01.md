# Zadání R01 – Scaffolding projektu, Docker Compose, tooling

Repozitář: `martinhoricky-bdo/rewrite-cobol`. Pracuj ve větvi **`codex/R01-scaffolding`** vytvořené z aktuální větve **`rewrite`**. Po dokončení otevři PR do **`rewrite`** (ne do `main`).

## Kontext (přečti před začátkem)

Přepisujeme legacy COBOL/DB2/CICS systém COBOL AIRLINES na webovou aplikaci Python/Django + PostgreSQL. Dokumentace je závazná:

- `AGENTS.md` – pravidla pro tebe (větve, co smíš měnit, obsah PR). Dodržuj je beze zbytku.
- `docs/rewrite/03-target-architecture.md` – stack, struktura `app/`, Docker Compose, Makefile (kap. 3, 8, 9).
- `docs/rewrite/04-migration-plan.md` – tento krok je **R01**; tam je i šablona popisu PR.
- `docs/rewrite/02-functional-spec.md` kap. 0 a 2 – konvence (jazyk UI angličtina, datum/čas `Europe/Paris`, hlavička obrazovky).

Tento krok neobsahuje žádnou business logiku ani legacy tabulky. Cílem je spustitelná kostra, na které budou stavět kroky R02+ (modely, seed, auth, obrazovky).

Nesmíš měnit nic mimo `app/` a `docs/rewrite/CHANGELOG.md`. Nevytvářej `.github/workflows/`. Legacy adresáře (`CICS/`, `COB-PROG/`, `DB2/`, `AS-400/`, `VIDEOS/`, kořenový `README.md`) jsou read-only.

## Rozsah – co vytvořit

Vše v adresáři `app/` (nový). Verze: Python 3.12, Django 5.1.x, PostgreSQL 16.

### 1. Projekt a závislosti

- `app/pyproject.toml`:
  - `[project]` název `cobol-airlines`, `requires-python = ">=3.12"`, závislosti: `Django>=5.1,<5.2`, `psycopg[binary]>=3.1`, `django-environ>=0.11`, `argon2-cffi>=23`, `gunicorn>=22`.
  - `[project.optional-dependencies] dev`: `pytest>=8`, `pytest-django>=4.8`, `factory-boy>=3.3`, `freezegun>=1.4`, `ruff>=0.5`.
  - `[tool.ruff]`: `line-length = 100`, `target-version = "py312"`, `[tool.ruff.lint] select = ["E", "F", "I", "UP", "B", "DJ"]`, výjimky jen pro migrace (`per-file-ignores` `"*/migrations/*" = ["E501"]`).
  - `[tool.pytest.ini_options]`: `DJANGO_SETTINGS_MODULE = "config.settings.test"`, `testpaths = ["tests"]`, `python_files = ["test_*.py"]`, `addopts = "-q --strict-markers"`.
- `app/manage.py` (standardní, výchozí `DJANGO_SETTINGS_MODULE=config.settings.dev`).
- `app/config/__init__.py`, `config/urls.py`, `config/wsgi.py`, `config/asgi.py` (může být jen wsgi).
- `app/config/settings/base.py`:
  - konfigurace přes `django-environ`: `SECRET_KEY`, `DEBUG` (default False), `ALLOWED_HOSTS` (list, default `["localhost", "127.0.0.1"]`), `DATABASE_URL` (default `postgres://airlines:airlines@localhost:5432/airlines`), `LEGACY_ROOT` (Path, default `BASE_DIR.parent`, tj. kořen repozitáře) – načítá `.env` z `app/`, pokud existuje.
  - `INSTALLED_APPS`: Django defaults (`admin`, `auth`, `contenttypes`, `sessions`, `messages`, `staticfiles`) + `core`, `accounts`.
  - `AUTH_USER_MODEL = "accounts.User"` (musí být nastaveno **od první migrace**, viz níže).
  - `PASSWORD_HASHERS`: Argon2 první, PBKDF2 jako druhý.
  - `LANGUAGE_CODE = "en"`, `TIME_ZONE = "Europe/Paris"`, `USE_TZ = True`, `USE_I18N = True`.
  - `TEMPLATES` s `DIRS = [BASE_DIR / "templates"]`, context processors včetně `messages` a `core.context_processors.header`.
  - `STATIC_URL = "/static/"`, `STATICFILES_DIRS = [BASE_DIR / "static"]`, `STATIC_ROOT = BASE_DIR / "staticfiles"`.
  - `SESSION_COOKIE_AGE = 8 * 60 * 60`, `SESSION_COOKIE_HTTPONLY = True`, `CSRF_COOKIE_HTTPONLY = True`.
  - `LOGIN_URL = "/login/"`, `LOGIN_REDIRECT_URL = "/"`, `LOGOUT_REDIRECT_URL = "/login/"` (samotné views vzniknou v R04).
  - `DEFAULT_AUTO_FIELD = "django.db.models.AutoField"` (legacy tabulky mají `INT`, ne `BIGINT`).
  - `LOGGING`: konzole, úroveň INFO pro `cobol_airlines.*` loggery, WARNING jinak.
- `config/settings/dev.py`: `DEBUG = True`, `ALLOWED_HOSTS = ["*"]`, `INTERNAL_IPS`.
- `config/settings/test.py`: dědí z base, `PASSWORD_HASHERS` jen MD5 (rychlost testů), `DEBUG = False`.
- `config/settings/prod.py` **nevytvářej** (krok R18).

### 2. Aplikace `accounts` (jen minimální uživatel)

- `app/accounts/models.py`: `class User(AbstractUser): pass` s `class Meta: db_table = "accounts_user"`. Nic víc – `Employee`, `Department` přijdou v R02. Důvod: vlastní model uživatele musí existovat před první migrací `auth`.
- `accounts/admin.py`: registrace `User` přes `UserAdmin`.
- Migrace `accounts/migrations/0001_initial.py` vygenerovaná `makemigrations`.

### 3. Aplikace `core`

- `core/views.py`:
  - `home` → `GET /` → šablona `core/home.html`, obsahuje text `COBOL AIRLINES` a `Programming at heights`. Zatím bez přihlášení.
  - `healthz` → `GET /healthz/` → `JsonResponse({"status": "ok", "db": True})`; `db` se zjistí dotazem `SELECT 1` přes `django.db.connection`; při výjimce vrátí `{"status": "error", "db": False}` se stavem 503.
- `core/context_processors.py`: `header(request)` vrací `{"now_local": timezone.localtime(), "app_title": "COBOL AIRLINES", "app_subtitle": "Programming at heights"}`.
- `core/urls.py` + zapojení v `config/urls.py` (včetně `admin/`).
- Šablony:
  - `templates/base.html`: `<!doctype html>`, `<html lang="en">`, `<head>` s `<title>{% block title %}COBOL AIRLINES{% endblock %}</title>`, odkaz na `static/pico.min.css`, `static/app.css`, skript `static/htmx.min.js` (s `defer`). Tělo: `<header>` s názvem aplikace, podtitulkem a datem/časem (`{{ now_local|date:"d/m/Y" }}`, `{{ now_local|time:"H:i:s" }}`) – rekonstrukce hlavičky CICS map (`DATE:`, `TIME:`); `{% block nav %}{% endblock %}` (prázdné; menu podle role přijde v R04); oblast hlášek `{% if messages %}` s `<article class="msg msg-{{ message.tags }}">`; `<main class="container">{% block content %}{% endblock %}</main>`; `<footer>` s textem `F3=EXIT` nahrazeným větou „Use the menu to navigate.“ (jen placeholder).
  - `templates/core/home.html` dědí z `base.html`.
- Statika: `static/pico.min.css` (Pico CSS 2.x, classless nebo standard build), `static/htmx.min.js` (htmx 2.x), `static/app.css` (drobné vlastní styly hlavičky a hlášek: chyba červeně, info zeleně – ekvivalent `MSG1`/`MSG2`). Soubory **vendoruj do repa** (stáhni z oficiálních release). Žádné odkazy na CDN. Pokud v prostředí není síť, vytvoř `pico.min.css` jako minimální vlastní stylesheet (max. 50 řádků) a `htmx.min.js` jako prázdný soubor s komentářem a **uveď to v popisu PR** jako odchylku.

### 4. Docker a Makefile

- `app/Dockerfile`: `FROM python:3.12-slim`, systémové balíčky jen nutné (`libpq` je v `psycopg[binary]` zabalené, takže typicky nic), `WORKDIR /app`, `COPY pyproject.toml`, `pip install -e .[dev]`, `COPY . .`, `EXPOSE 8000`, výchozí `CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]`.
- `app/docker-compose.yml` (bez klíče `version`):
  - `db`: `postgres:16`, env `POSTGRES_DB=airlines`, `POSTGRES_USER=airlines`, `POSTGRES_PASSWORD=airlines`, port `5432:5432`, volume `pgdata`, healthcheck `pg_isready -U airlines`.
  - `web`: `build: .`, `command: python manage.py runserver 0.0.0.0:8000`, `volumes: [".:/app", "..:/legacy:ro"]`, `ports: ["8000:8000"]`, env `DJANGO_SETTINGS_MODULE=config.settings.dev`, `DATABASE_URL=postgres://airlines:airlines@db:5432/airlines`, `LEGACY_ROOT=/legacy`, `SECRET_KEY=dev-only-not-secret`, `depends_on: db: condition: service_healthy`.
  - `e2e`: `profiles: ["e2e"]`, `image: mcr.microsoft.com/playwright/python:v1.47.0-jammy`, `working_dir: /app`, `volumes: [".:/app"]`, env `BASE_URL=http://web:8000`, `command: sh -c "pip install -q -e .[dev] pytest-playwright && pytest -q tests/e2e"`, `depends_on: [web]`. Adresář `tests/e2e/` založ s prázdným `__init__.py` (testy přijdou v R12).
- `app/Makefile` s cíli přesně dle `03-target-architecture.md` kap. 8.3: `up`, `down`, `migrate`, `seed` (zatím `python manage.py seed_demo` – příkaz vznikne v R03; do té doby cíl existuje a selže srozumitelně), `test`, `e2e`, `lint`, `check` (= `lint` + `test`), `shell`. Všechny spouštějí příkazy přes `docker compose exec web …` (u `e2e` přes `docker compose --profile e2e run --rm e2e`). Na začátku Makefile `.PHONY` a proměnná `COMPOSE ?= docker compose`.
- `app/.env.example` (`SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `DATABASE_URL`, `LEGACY_ROOT`), `app/.gitignore` (`.env`, `__pycache__`, `*.pyc`, `staticfiles/`, `.pytest_cache/`, `.ruff_cache/`), `app/.dockerignore`.

### 5. Testy

- `app/tests/__init__.py`, `tests/conftest.py` (zatím jen `pytest_plugins` nebo prázdný; DB fixture zajišťuje `pytest-django`).
- `tests/views/test_healthz.py`: `GET /healthz/` → 200, JSON `{"status": "ok", "db": true}` (označ `@pytest.mark.django_db`).
- `tests/views/test_home.py`: `GET /` → 200, obsahuje `COBOL AIRLINES`; hlavička obsahuje dnešní datum ve formátu `d/m/Y` (použij `freezegun` a `timezone.localdate()`).

## Akceptační kritéria

1. `cd app && make up && make migrate` proběhne z čistého stavu; `curl http://localhost:8000/healthz/` vrátí `{"status": "ok", "db": true}`; `http://localhost:8000/` zobrazí stránku s hlavičkou (název, podtitulek, datum, čas).
2. `make check` je zelený: `ruff check .` a `ruff format --check .` bez nálezů, `python manage.py check` bez chyb, `python manage.py makemigrations --check --dry-run` hlásí „No changes detected“, `pytest` prochází (min. 4 testy výše).
3. `docker compose config` je validní; služba `e2e` je v profilu `e2e` a bez profilu se nespouští.
4. V `app/` není žádný odkaz na externí CDN (ověř `grep -r "cdn\." app/templates app/static`).
5. `git diff --stat rewrite..HEAD` obsahuje jen soubory v `app/` a `docs/rewrite/CHANGELOG.md`.
6. Nic v `.github/`.

## Jak ověřit lokálně (spusť před otevřením PR)

```
cd app
make up
make migrate
curl -s http://localhost:8000/healthz/
make check
make down
```

Posledních ~10 řádků výstupu `make check` vlož do popisu PR.
