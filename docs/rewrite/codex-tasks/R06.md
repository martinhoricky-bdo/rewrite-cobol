## Rozsah

### 1. Služba (`sales/services.py`)

`search_tickets(*, ticketid=None, clientid=None, firstname=None, lastname=None, flightnum=None, flightdate=None) -> QuerySet[Ticket]` – předpokládá už vyčištěné vstupy z formuláře:

1. `ticketid` → `Ticket.objects.filter(ticketid=ticketid.upper())`, ostatní parametry ignoruje.
2. jinak `clientid` → `filter(client_id=clientid)`, + volitelně `flight__flightnum__iexact`, `flight__flightdate`.
3. jinak `firstname` + `lastname` → `filter(client__firstname__iexact=..., client__lastname__iexact=...)` + volitelně číslo letu / datum.
4. `select_related("client", "flight", "flight__airportdep", "flight__airportarr", "buy")`, řazení `flight__flightdate, flight__deptime, ticketid`.

### 2. Formulář (`sales/forms.py: TicketSearchForm`)

| Pole | Typ |
|---|---|
| `ticketid` | `CharField(max_length=10, required=False)` |
| `clientid` | `IntegerField(min_value=1, required=False)` |
| `firstname`, `lastname` | `CharField(max_length=30, required=False)` |
| `flightnum` | `CharField(max_length=6, required=False)` (label `FLIGHT NUM`) |
| `flightdate` | `DateField(required=False, input_formats=["%Y-%m-%d"])`, chyba → `E_FLT_02` |

`clean()`: ořez; pokud není `ticketid`, ani `clientid`, ani (`firstname` a `lastname`) → `ValidationError(E_TKT_01)` (i když je vyplněno jen `flightnum`/`flightdate`, nebo jen jedno ze jmen). `ticketid` neodpovídající `^CB\d{8}$` (case-insensitive) → formulář je validní, ale view zobrazí `E_TKT_02` a prázdný seznam (legacy: prostě nic nenajde). Metoda GET, bez parametrů se validace nespouští.

### 3. Views a šablony

- `GET /sales/tickets/` (`sales:ticket_search`), `@role_required(Role.SALES, Role.CEO)`: formulář vlevo, výsledky jako tabulka `TICKET ID | FIRST NAME | LAST NAME | FLIGHT NUM | FLIGHT DATE | TIME DEP | TIME LAND | AIRPORT DEP | AIRPORT LAND | SEAT`, řádek odkazuje na detail; stránkování po 10 (`partials/pagination.html`); prázdný výsledek → `messages.info(E_TKT_02)`.
- `GET /sales/tickets/<ticketid>/` (`sales:ticket_detail`), stejné role: 404 s hláškou `E_TKT_03` (vlastní `404.html` s obecným textem + `messages`), jinak všechna pole dle UC-S03 (letiště s městem: `CDG – Roissy`), blok „Purchase“ (`BUYID`, `buydate buytime`, prodejce `empid – jméno`, `price EUR`); tlačítka `Back to search`, placeholder odkaz `Print boarding pass` (`/sales/tickets/<ticketid>/boarding-pass/`, view vznikne v R07) a odkaz na nákup `/sales/buys/<buyid>/` (R10/R11).
- Navigace: `MENU[Role.SALES]` + `("Search ticket", "sales:ticket_search")`; `MENU[Role.CEO]` také.

### 4. Testy

- `tests/unit/test_search_tickets.py`: `ticketid` přebije ostatní parametry; `clientid` + `flightnum`; `clientid` + `flightdate`; `clientid` + oboje; jméno case-insensitive (`maxime`/`DUPRAT`); jméno + číslo letu; řazení; `select_related` neprovádí N+1 (`django_assert_num_queries` ≤ 2 pro seznam 10 letenek).
- `tests/unit/test_ticket_search_form.py`: jen `flightnum` → `E_TKT_01`; jen `firstname` → `E_TKT_01`; `clientid=0` → chyba pole; špatné datum → `E_FLT_02`; validní kombinace.
- `tests/views/test_ticket_search.py`: hlášky `E_TKT_01`, `E_TKT_02` (včetně `ticketid=XYZ`), stránkování, detail 200 s obsahem (`TICKET ID`, jméno, `SEAT`), detail 404 + `E_TKT_03`, oprávnění (`sales`, `ceo` 200; `hr`, `crew`, `schedule` 403).
