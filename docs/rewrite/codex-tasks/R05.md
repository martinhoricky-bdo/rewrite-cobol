## Rozsah

### 1. Služba (`operations/services.py`)

- `free_seats_subquery()` / anotace: `Flight.objects.annotate(sold=Count("tickets"))` a `free_seats = F("airplane__numseats") - F("sold")` (použij `Subquery`/`Count` tak, aby nevznikaly duplicity při dalších joinech).
- `search_flights(*, flightnum: str | None, flightdate: date | None, airportdep: str | None, airportarr: str | None, today: date) -> QuerySet[Flight]`:
  - všechny nevyplněné parametry se ignorují, vyplněné se kombinují AND;
  - `flightnum` porovnání `iexact` po `strip()`; letiště `iexact` po `strip()`;
  - `flightdate is None` → `flightdate >= today`;
  - `select_related("airplane", "airportdep", "airportarr")`, anotace `sold`, `free_seats`;
  - řazení `flightdate, deptime, flightnum`.
- Funkce nevalidační: prázdné vstupy řeší formulář.

### 2. Formulář (`sales/forms.py: FlightSearchForm`)

| Pole | Typ | Validace |
|---|---|---|
| `flightnum` | `CharField(max_length=6, required=False)` | – |
| `flightdate` | `DateField(required=False, input_formats=["%Y-%m-%d"])` | chybný formát → `E_FLT_02` (nahraď výchozí chybovou hlášku) |
| `airportdep` | `CharField(min_length=3, max_length=4, required=False)` | |
| `airportarr` | `CharField(min_length=3, max_length=4, required=False)` | |

`clean()`: pokud nic nevyplněno (po ořezu) → `ValidationError(E_FLT_01)`. Formulář se používá metodou GET (`form = FlightSearchForm(request.GET or None)`); při prvním zobrazení (bez parametrů) se validace nespouští a nezobrazí se chyba.

### 3. View a šablona

- `sales/urls.py` (`app_name = "sales"`), zapoj do `config/urls.py` pod prefixem `/sales/`.
- `GET /sales/flights/` (`sales:flight_search`), `@role_required(Role.SALES, Role.CEO, Role.SCHEDULE, Role.CREW)`.
- Při nevalidním formuláři: chybová hláška přes `messages.error` (+ chyby u polí), tabulka prázdná. Při validním: `Paginator(qs, 10)`, parametr `page`; prázdný výsledek → `messages.info(E_FLT_03)`.
- Šablona `sales/flight_search.html`: formulář (labely `FLIGHT NUM`, `DATE` s placeholderem `YYYY-MM-DD`, `DEP AIRPORT`, `LAND AIRPORT`, tlačítko `Search`), tabulka `FID | TDEP | TLAND | DEP | LAND | PLACES | DATE | PRICE | ` s odkazem `Sell` → `/sales/sell/?flightnum={{ f.flightnum }}&date={{ f.flightdate|date:"Y-m-d" }}` (literální cesta; view vznikne v R09). `TDEP`/`TLAND` formát `H:i`, `PRICE` formát `120.99 EUR`. Stránkování `partials/pagination.html` (nový sdílený partial: Previous/Next, `page n/N`, zachová ostatní query parametry).
- Navigace: `core/navigation.py` – `MENU[Role.SALES]` přidej `("Search flight", "sales:flight_search")`; `ROLE_HOME[Role.SALES] = "sales:flight_search"`. Ostatním rolím s právem čtení (`CEO`, `SCHEDULE`, `CREW`) přidej stejnou položku do jejich menu.

### 4. Testy

- `tests/unit/test_search_flights.py` (`django_db`, factories): každá kombinace vstupů (jen číslo letu → jen lety `>= today`; jen datum; číslo + datum; letiště odletu bez data → `>= today`; odlet + přílet + datum; případ, kdy číslo letu a letiště nesouhlasí → prázdný výsledek); case-insensitive (`cb1104`, `cdg`); řazení; `free_seats` = `numseats − počet letenek` (vytvoř 2 letenky přes `TicketFactory`).
- `tests/views/test_flight_search.py`: prázdný formulář s odesláním (`?flightnum=&flightdate=`) → hláška `E_FLT_01`; špatné datum → `E_FLT_02`; bez výsledků → `E_FLT_03`; 25 letů → 10 na stránce, `page=3` má 5; první zobrazení bez parametrů nemá chybu; oprávnění: `sales`, `ceo`, `schedule`, `crew` → 200, `hr`, `it`, `legal` → 403, anonym → redirect. Po přihlášení `sales` uživatele `/` přesměruje na `/sales/flights/`.
